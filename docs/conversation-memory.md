# 会话记忆：升级与验收

实现顺序为原文归档/摘要/预算，再接用户确认的长期记忆与管理入口；复用 MySQL、Redis 和当前 LLM，不增加框架或向量索引。

## 先升级数据库

已有部署先备份数据库和 Redis，在维护窗口停止旧版后端写入，再按顺序执行：

1. `docs/migrations/20260903_conversation_memory.sql`
2. `docs/migrations/20260903_user_memories.sql`
3. 检查 `configs/config.yaml` 的模型上下文配置，启动新版后端。

SQL 可重复执行，不删除旧表或原文。若曾手工创建旧结构 `conversations` 表，必须先检查并回填结构；`CREATE TABLE IF NOT EXISTS` 不会升级已有旧表，不能直接宣称迁移成功。全新部署的 `docs/ddl.sql` 已包含三张新表。**本次代码实施未连接或修改真实业务数据库。**

每个用户第一次读取会话时，会将 Redis 中仍存在的完整问答对原子迁入 MySQL。迁移失败保留 Redis 原文并返回错误；SQL 已有状态后不再导入旧缓存，Redis 断线也不影响已迁移用户的归档读写。旧版已经覆盖/过期的消息无法恢复。滚动混跑旧版与新版会丢失只写 Redis 的新消息，因此需要上述维护窗口。管理端只列已迁入 SQL 的用户，未迁移用户在首次访问会话后出现。

## 实际输入与存储

| 层 | 存储与上限 | 用法 |
| --- | --- | --- |
| 原文归档 | `conversations`，完整成功问答追加，不自动过期 | 分页回查；不全量输入模型 |
| 近期工作上下文 | 从 SQL 取最近最多 6 对，默认预算 4000 | 指代、澄清衔接；保留完整问答对 |
| 会话摘要 | `conversation_states`，默认预算 3000，最多 16 项 | 主题、实体、约束、决定、待解决问题及来源轮次 |
| 长期记忆 | `user_memories`，每用户最多 50 条，召回最多 5 条/预算 1500 | 仅用户明确确认，按用户、范围、关键词及到期时间筛选 |
| Redis 缓存 | 最近 20 条，7 天 | 非权威；清空/过期不删除 SQL 原文 |

每轮先取得记忆与状态的原子版本快照，再摘要将离开近期窗口的原文前缀：`旧摘要 + 新增待压缩轮次 → 新摘要`。每批最多 4 轮、每请求最多 2 批；成功 CAS 后推进 `summary_until`，大批积压重试会从已完成水位继续。失败/取消/坏 JSON/未知来源/超预算不推进水位、不删除原文。不会用每次重读全史来生成摘要。

长助手回答摘要输入最多 2000 字节，标记节选；用户问题通常完整输入，极长旧问题超预算时采用有界节选并持久保留 `omitted_user_content` 标记，避免永远卡在同一轮。摘要有损，不保证恢复原代码、表格、遗漏条件；依赖这些细节时应回查或澄清。新问题最多 4096 字符。

## 预算

```yaml
memory:
  enabled: true
  context_window_tokens: 32768
  max_input_tokens: 20000
  recent_tokens: 4000
  summary_tokens: 3000
  long_term_tokens: 1500
  summary_timeout_seconds: 15
```

当前用 UTF-8 字节数加消息封装开销做**保守估计**，不是模型精确 tokenizer；中文通常会更早触发压缩。`context_window_tokens` 必须按实际部署模型配置，32768 只是默认值，不能当作所有模型的规格。

全部模型调用在发送前检查：`输入预算 <= min(max_input_tokens, context_window_tokens - 输出预留 - 1024)`。摘要/规划/依赖绑定输出上限 1024，最终输出使用 `llm.generation.max_tokens`（未设时预留 8192）。模型提示、当前问题、记忆和资料都计入。依赖绑定只输入实际前置步骤的资料，超限裁掉低排名候选但保留每个前置步骤至少一条，来源 ID 和引文不变。最终回答先剔除低排名非必要资料并重建引用编号，始终保护依赖桥接证据和每个非空分支的首条来源；必要时再移除低优先级长期记忆。必需内容仍放不下就明确标记绑定失败或报错，不截断引用或静默丢失当前问题。降低摘要预算后若已有摘要超限，需要恢复合适预算，不会静默削掉旧约束。

关闭 `memory.enabled` 只停用摘要生成与长期记忆注入，原文归档、近期窗口预算和已确认记忆管理仍保留。未迁移或表不存在时不会退回仅 Redis 写入。预算配置过小仍可能无法运行，应修正配置。

## 长期记忆与遗忘

聊天页“记忆与历史”可以查看、明确确认新增、修改、删除记忆，并分页读取完整问答归档。没有后台从所有聊天自动提取“事实”的任务；偏好/项目约束/决定由用户确认后保存，不保存普通助手猜测。

- API：`GET/POST /api/v1/users/memories`，`PUT/DELETE /api/v1/users/memories/:id`。修改和删除必须带 `version`；新增/修改必须有 `confirmed:true`。归档：`GET /api/v1/users/conversation/archive?after=0&limit=20`，limit 为 1–100，使用返回的 `next_after` 翻页。
- 所有权来自登录身份，不接受请求指定其他用户；记忆不按组织共享。`scope=global` 的偏好可普遍使用，其他条目需要关键词命中；非 global 范围还必须在当前问题或明确追问上下文中出现。短指代追问只参考最近用户问题，近期原文为空时参考摘要的主题/实体；普通新问题不继承旧主题。
- 召回是有界关键词匹配，不能可靠覆盖同义词。先通过实际漏召回评测决定是否需要语义检索，不预先增加向量数据库。范围不是权限字段，用户隔离始终按数据库 owner 执行。
- 修改、删除和到期清理与上下文重置在同一事务：清空摘要，`context_after=summary_until=last_turn`，推进版本。旧原文不再自动输入模型，避免被删除信息从旧摘要/近期上下文重新出现。原文归档仍在，可显式回查；这不是物理删除整个聊天记录，也不是撤回已发给模型的数据。
- 到期清理发生在下一次列表/快照读取，**没有后台定时清理保证**。聊天在摘要完成及最终生成前复核快照；之后仍在生成的旧请求在保存时由 CAS 拒绝。已经送给模型或流式显示的文字不能撤回。UI 生成期间禁止手工变更，其他浏览器的变更仍可能使当前轮失败，刷新/重试即可。
- 输入拦截常见密码/密钥格式，但这不是完整 DLP。不要保存凭证。摘要/记忆以不可信数据进入模型，不提升为系统指令，也不代替知识库事实证据与实时权限检查。

## 验收

离线回归（不调用真实模型）：

```powershell
go test ./...
go test -race ./internal/service ./internal/repository ./internal/handler
node --test frontend/src/service/request/index.test.mjs frontend/src/store/modules/chat/index.test.mjs frontend/src/views/chat/modules/memory-panel.test.mjs
```

仓库测试中小型 SQL 驱动验证 SQL 条件、事务顺序和回滚路径，**不能代替 MySQL 真实锁行为验证**。真实集成需手动准备名字以 `_test` 结尾的隔离 MySQL 测试库，执行两份迁移；然后设置 `PAISMART_TEST_MYSQL_DSN`、`PAISMART_TEST_REDIS_ADDR`（可选密码），运行 `go test ./internal/repository -run TestConversation -v`。测试不自动建表或清空数据库；未配置则明确跳过。详见对应 integration test 的环境变量和保护条件。

手工重点验收：累计 15 轮后旧约束仍可追问；修正后的约束优先；取消/模型断流不保存半截答案；查询归档原文未改变；A/B 项目同关键词不串范围；换账号无记忆泄露；删除/修改/到期后旧上下文不会自动恢复；记忆变更与慢生成竞争时拒绝旧写入。精确历史代码/表格仅凭摘要不能补全。

离线测试只证明编排与边界，不证明真实模型的摘要忠实度和指代准确率。上线前固定模型/提示词/脱敏长对话测条件保留、纠正、否定、范围隔离、过期及首字延迟；本次没有进行生产数据库联调、真实模型质量或压测。
